# 夜航 V4 · CITY ACRO

## 两个主要交付物

1. `技术方法论.html`：双击即可离线阅读。14 条有源码证据的方法，每条包含原理、代价和 prompt；末尾附这次模拟器的实际验收结果。
2. `夜航模拟器.html`：完整自包含的电脑端三维飞行游戏。可直接打开，用键盘或标准 USB/蓝牙手柄操作。首页地图列表分三列，向下滚动可选后续地图。可随时切换城市、码头、雪山极光、秋日丛林、海湾、夏日乡间、洪水中的果园与霓虹夜城；切图会重建场景、天空、雾与碰撞边界，预览镜头自动环绕。地图选择会记在浏览器里，也可用 `?map=city|saltline|aurora|autumn|bay|summer|orchard|neon-city` 指定。手机控制需启动下述本地服务。

## 手机当手柄

完整解压后，在「夜航运行包」外面那层文件夹双击对应的启动文件，保留打开的终端窗口。

- Windows 双击 `启动夜航-Windows.cmd`。同目录的 `start-nightflight.ps1` 由启动器自动调用。
- macOS 双击 `启动夜航.command`，支持 Apple 芯片和 Intel 芯片。

浏览器会自动打开游戏，右侧显示二维码和「重连 / 检查连接」按钮。手机、电脑连接同一 Wi-Fi，手机扫码后横屏使用。电脑点一次「开启声音」可解锁音频。

- 左杆：纵向油门，横向偏航；油门松手保持，偏航松手回中。
- 右杆：纵向俯仰，横向横滚；松手回中的是角速度指令，不是飞行姿态。
- 油门先拉到最底部，再点「解锁 / 停桨」。现在从地面出发；零油门解锁后可停留等待，缓推至约 20%–25% 起飞，不会在准备期间从空中坠毁。
- 手机「复位」会清零油门并让机体回到出发点；失联、手机切后台会让电脑停桨并暂停；恢复连接后需要重新解锁。
- 支持一部手机配对。多开电脑游戏标签页会同时接收控制，建议只保留一个飞行页面。
- 手机右上角「隐藏」会把电脑画面用一张图片全屏盖住并静音，按钮变成「显示」；再点一次或电脑按 Esc 恢复。图片来自本文件夹的「隐藏」目录：有多张时每次随机挑一张，增删或替换图片后无需重启服务，下次隐藏即生效（支持 png/jpg/jpeg/webp/gif/avif）。飞行不会因此暂停，只是看不见画面，建议先停桨再隐藏。
- 二维码里有本次启动的随机会话码；重启服务后重新扫码。
- 初次运行如果 macOS 询问本地网络访问，请允许浏览器/Node 使用本地网络。手机接入访客 Wi-Fi、AP 隔离或电脑防火墙阻断时可能连不上。
- 二维码默认使用第一张网卡的地址；有多张网卡时，直接打开 `http://127.0.0.1:端口/?pair=1` 或点「重连 / 检查连接」刷新。手机与电脑不在同一网段、AP 隔离或防火墙拦截时都会连不上。
- 手机页横屏使用即可，不再提供手机全屏按钮；手机无需 WebGL，只发送操控数值。
- 缓推油门约 20%–25% 即可离地。当前出厂参数的理论悬停油门约 12.9%，低于它不会持续爬升。

### 延迟在哪里看

电脑右下 HUD 只显示一个总延迟「延迟 xx ms」（手机 RTT 的一半 + 传输 + 生效前），手机中间仍保留「延迟约 … · 上行 · 传输 · 帧」明细。合计超过 80ms 变黄，150ms 变红。

- 上行：手机发出控制包并收到回执的往返时间的一半，主要是手机 Wi-Fi 与浏览器开销；这是最常见的延迟来源。
- 传输：本机服务把包广播到电脑页面所花的时间，正常是个位数到十几毫秒。它偏大说明电脑页面被切到后台或主线程卡住。
- 生效前：电脑收到包到下一帧真正使用它的时间，取决于帧率；画面越卡这一项越大。
- 手机状态数字每 150ms 才回传一次，所以高度、油门读数本身最多滞后约 0.15 秒；这是显示滞后，不会加在操控上。
- 手机页面切到后台或锁屏会停发控制包并触发暂停，这是省电保护。要测延迟请让手机页面保持前台。
- 改完服务端后需重新双击对应系统的启动文件，新时间戳才会生效。

启动器会检查电脑上的 Node.js 22 或更新版，以及用于录屏转 MP4 的 FFmpeg。首次缺少组件时需要联网，下载会经过 SHA-256 校验并缓存到当前用户目录。已有可用组件时可离线启动。游戏和二维码已随运行包提供，无需安装 npm 依赖或使用管理员权限。

游戏需要支持 WebGL 2 的浏览器和显卡。FFmpeg 配置失败时，游戏和手机手柄仍可使用，WebM 录屏会保留原格式。若 Node.js 配置失败，启动器会尝试直接打开支持键盘和实体手柄的离线页面。Windows 首次配对若弹出防火墙提示，可允许 Node.js 访问当前的专用网络。

按 Ctrl+C 可关闭服务。启动器会自动选择空闲端口，每次启动后请扫描当前窗口对应的二维码。

## 键盘 / 实体手柄

键盘：↑↓ 油门增减；A/D 偏航；W/S 俯仰；←→ 横滚；Space 解锁/停桨；R 复位；F 原地扶正；P 暂停；[ ] 镜头上仰角；Esc 菜单。

标准 Gamepad 布局：左杆油门/偏航，右杆俯仰/横滚，A 解锁，B 复位，X 原地扶正。普通游戏手柄左杆纵轴会机械回中，意味着油门回到 50%，与不回中油门遥控器不同；本版不提供任意 HID 轴重映射，非标准遥控器需要后续适配。该功能的真设备尚未实测。

电脑设置面板支持即时调节：摄像头仰角、垂直 FOV、重力、终端下落速度、质量、最大总推力、二次空气阻力、电机响应、角速度响应、横滚/俯仰/偏航各自的中心灵敏度、满杆角速度与 Expo，以及死区。设置自动保存在当前浏览器；改变地址或浏览器会使用独立设置。

## 转向太灵敏怎样调

横滚与俯仰满杆角速度范围均为 0–1000°/s，偏航满杆角速度范围为 0–1200°/s。满杆值是实际转动指令的上限，低于中心灵敏度时中心也会受限；设为 0 时对应轴的摇杆转动指令为零。当前已保存配置和出厂默认值不会自动修改。

手机或手柄的小幅操作太敏感，先降低对应的「中心灵敏度」；中等推杆太猛，可提高 Expo；大幅动作太快，再降低「满杆角速度」。可以先试横滚/俯仰：中心 30、满杆 150、Expo 0.6；偏航：中心 20、满杆 100、Expo 0.6，再按手感调整。这组数值是本游戏的慢速练习起点。

键盘按下方向键或姿态键会直接给满杆输入，中心灵敏度和 Expo 无法细分按键幅度，优先调低满杆角速度。M/Acro 模式松杆不会回平；降低角速度能让转动变慢，但不会自动消除已经形成的倾斜或侧滑。

## 怎样消除“飞气球感”

以出厂参数为基准：重力 9 档、0.9 kg 质量、65 N 总推力，静止水平机体的理论悬停油门约 22%。重力滑杆为 4–16 档，默认 9 档；往上推会明显加大下坠和悬停油门。不要通过降低重力来降低难度；先降低满杆角速度或调整 Expo。前倾会分走向上的推力，转弯和高速前飞要补油。松油会下落，倒飞时推力也会向下。相机仰角只改变观看方向，不替你保持高度。

「飞行调校 → 终端下落速度」范围 15–100 m/s，默认 35 m/s。想让收油后最终掉得更快，调高此项；想让刚收油时加速更快，用「下降加速度」或调重力。零推力下落时，二次阻力让垂直速度逐渐接近设定值，达到附近需要足够的下落距离。可在高处先稳住高度再把油门归零，观察 HUD 的垂直速度和垂直加速度。

「下降加速度」范围 0–34 m/s²，默认 0，只在下落时平滑叠加：不改悬停与爬升，也不改上面设定的终端下落速度。觉得收油后“像纸板飘下来”，先确认油门确实回到 0%，再逐档提高这一项。

本版是简化的 Acro 飞行模型：四元数姿态、机体角速度控制、推重比、惯性、二次阻力、电机滞后、240Hz 固定步长。角速度控制用一阶响应近似，不是完整 Betaflight PID/电机混控或高精度空气动力学模型；没有风、螺旋桨尾流、桨洗、真实电池/电机温升模型。可以用来体验 M 档动作和城市飞行，不宣称能替代真机训练软件。

## 碰撞后继续飞行

- 建筑、地面、屋顶、车辆、杆件和门框沿用已有碰撞体。正撞小幅反弹，擦碰沿表面滑动并损失少量速度；高速重撞也不会扣血、停桨或暂停。低速触地落稳，重落地先弹起再落稳。
- 碰撞反馈包含实际速度变化、有限姿态扰动和短促碰撞声。声音需先在电脑开启；单次姿态扰动最多约 1.4°，不会自动回平。碰撞采用 28cm 保守包络与路径扫掠，是简化的练习型反馈，不是完整机架刚体仿真。
- 倒扣或倾斜落地后，把油门归零并停稳，点击电脑/手机「原地扶正」、按 F 或手柄 X；保留当前位置和水平朝向。扶正不会自动解除手动暂停或重新解锁；若本来已解锁，扶正后推油门可继续起飞。
- 地图边缘前 4m 对向外速度逐渐减速，极限处小幅挡回，不会暂停。已有可飞范围不变；部分装饰和远景仍无碰撞体。
- R / 手机「复位」仍回起飞点。手机断连、切后台、窗口失焦或严重卡顿的停桨暂停保护继续生效。

## 地图和画面范围

按所给夜景照片提取深蓝夜空、暖色窗灯、玻璃高楼、施工框架与红色塔吊。它是程序生成的风格化场景，不是照片测绘或建筑逐栋还原。可飞范围 x/z 为 ±285m、最高 240m；远方楼群是不可飞装饰。撞击会减速、小幅反弹或沿表面滑动，不会停桨或暂停；边界会柔和减速挡回，转向即可继续。施工楼的楼板与柱子可碰撞，中间空隙可以穿行。

默认渲染按浏览器 CSS 像素 1×，不会直接按 Retina 物理像素翻倍。设置里有 0.7× 省电、1× 均衡、1.4× 精细；选择画质明确显示，不做隐藏降档。阴影只计算静态城市，飞行器本身不可见，所有楼体不发生移动；物体移动后需重新计算阴影。

「霓虹夜城」采用 [Cyber Web City](https://github.com/greggman/cyber-web-city) 原版 WebGPU 城市生成与着色，默认比例有 13.2 × 13.2 公里可飞城区。玩家飞船和驾驶舱已移除，使用夜航的 Acro 飞控与程序碰撞。普通开局会从地图列表随机选一张。霓虹夜城每次打开页面随机生成，同一页面切图和按 R 复位沿用当前城市。港口传送牌分散在各街区，迎着牌面穿过即可进入码头。点击「复制本城链接」保留种子和主题，也可用 `?map=neon-city&theme=chongqing&seed=250126` 指定。Chrome 等支持 WebGPU 的浏览器可使用原版渲染，其他环境使用原有的 WebGL 兼容地图。

「性能 · 120 FPS 目标」按 8.3 ms 帧预算调节内部渲染分辨率与装饰距离，优先保留近景细节，使用轻微锐化和较少的近处历史帧混合。内部渲染比例不低于 64%，默认按窗口尺寸输出，关闭全屏泛光和色差。「原画 · 固定」使用 1× CSS 分辨率和原版反射。两档及 WebGL 兼容版均关闭雨雾。飞行默认上限为 120 FPS，实际帧率受显示器刷新率与 GPU 负载限制。可在飞行设置手动限到 60 FPS。菜单和暂停保留一帧，窗口或画质调整时刷新。录屏采样最高 60 FPS，输出尺寸固定，内部渲染可继续调节。位置记录和录屏自动使用当前画布。空中车辆使用原版速度，保留原版约八分之一的数量。地图画面、生成 Worker、着色器和常驻车流均由代码生成，许可证附在安装包和 HTML 内。

项目根目录的 `霓虹夜城-试飞.html` 是 WebGL 兼容版的 900 米独立样段。原版全城请从夜航地图列表打开。

海湾默认使用日落配色，夏日乡间沿着 960 米道路展开。画质设为 0.7× 可减少实时倒影和植被开销。首页预览以约 30 FPS 为目标。右下角 GPU 一行显示游戏渲染耗时和估算的单帧预算。飞行时 120 FPS 的预算约 8.3 ms，60 FPS 约 16.7 ms。耗时长期接近预算时，可试下一档画质。浏览器无法读到 GPU 计时时会显示「GPU —」。

「洪水中的果园」以《水之记忆》第三幕为参考，程序生成树列、古树枝拱、花瓣与暮色倒影。每次进入果园都会重新计时，35 秒后极光开始浮现。天空、水面、落花、白鹭、归栖鸟群、鱼跃和萤火虫每 100 秒循环，停在原地也能看到。花枝纹理由代码生成，水面实时反射。船、人物、桨和灯均为程序建模，船固定在树列之间。

电脑飞行设置和手机手柄设置都可选背景音乐，并独立调节背景音乐和螺旋桨音量。六首背景音乐均可离线循环播放。

- 「Bay Ride · 夜航」播放原 WAV 的前 141 秒。
- 「果园暮色 · 程序配乐」以 D 小调和慢速 6/8 拍合成，选中后生成约 40 秒的立体声循环。
- 「Calm Waters」「Day's End」「Field Of Fireflies」「Warm Horizon」由 Purrple Cat 创作，收录于《Mellow Skies》。游戏内嵌完整 MP3，按 CC BY 4.0 授权使用。[曲目来源](https://purrplecat.itch.io/mellow-skies) · [许可证](https://creativecommons.org/licenses/by/4.0/)

第一次在电脑点击或按键后可以播放音乐。BGM 音量拉到 0 会切换为关闭，再选曲时恢复到 50%。顶部「声音」按钮控制总声音。

## 源码与许可证

`source/` 是可编辑源码（含本地 Three.js）。在本目录 `npm install`，再 `npm run build` 重新生成单文件游戏、手机手柄的地图清单和二维码模块。编辑时需要开发依赖；玩游戏不需要安装这些依赖。`server.mjs` 使用 Node 标准库，`qr.cjs` 已打包二维码编码器。

新增地图时，在 `source/maps/index.js` 注册场景，并在 `source/maps/catalog.js` 追加地图 ID、名称和标签。地图清单决定两端的显示顺序。`npm run build` 会把同一份清单写入电脑端和手机端，发布前验证手柄能选中新增地图并让电脑成功切换。

Bay Ride / Summer Cycle by StarKnightt, MIT。两张地图及 Bay Ride 音乐的许可证与 Three.js、node-qrcode 许可证同在 `licenses/`。Betaflight 文档与开源实现用于核对 Acro 定义与 Actual Rates 数学关系；本作品没有嵌入整个飞控固件，默认机体参数为本模拟器选择的练习值。

## V2 修复与 iPhone 15 Safari 使用流程

上一版的空中出生点会导致零油门解锁后先坠地，触发碰撞暂停；手机没显示暂停状态，随后推杆看似无效。V2 已改为地面稳定起飞、正常低速触地不判撞毁，并将电脑的实际飞行状态、高度、速度、油门回传至手机。

1. 重新双击 `启动夜航.command`，扫描本次新二维码；手机顶部必须显示「夜航 V2」。旧页面需要关闭。
2. 手机点「解锁起飞」。确认手机显示「已解锁 · 推油门起飞」。断连后点手机上的「重新连接」即可重连，解锁前仍需油门归零。
3. 按住左杆圆点缓慢上拖，推至约 25%–30%。默认理论悬停油门约 12.9%；高于该值才会持续爬升。零油门不是悬停。
4. 起飞后轻推右杆：上推前俯、下推后仰、左右推横滚。M 档控制转动速度，松杆不会回正；想停止倾斜需要反向修正。
5. 手机直接显示电脑确认的状态；当前版碰撞可继续飞行，倒扣落地时油门归零后点「原地扶正」。左右杆均使用相对拖动，重新放手指不会把油门跳到 50%。

V2 已使用 iPhone 15 横屏设备配置及 WebKit 引擎进行从按钮解锁到机体/相机实际运动的闭环测试，并以 Chromium 原生双指触控做独立验证。这是本机浏览器模拟，尚不是一部真实 iPhone 15 的触屏手感与 Wi-Fi 延迟测试。

## V3 全屏、独立偏航与持久保存

- 电脑右上角「全屏」调用浏览器原生 Fullscreen API，隐藏地址栏/标签栏；进入全屏后顶部整排按钮自动隐藏，只在右上角留一个小圆形 ✕，点它或按 Esc 退出全屏并恢复按钮栏。需要你直接点击授权进入全屏，不能通过手机远程替电脑申请浏览器全屏。
- 最大总推力范围由 12–45 N 扩为 12–220 N，当前出厂默认为 65 N。想增加拉起力度可自行上调，面板实时显示推重比和理论悬停油门。
- 偏航（左手左右）现在有独立的中心灵敏度、满杆角速度和 Expo；横滚/俯仰不再跟着改变。
- 15 个飞行参数、画质和反向俯仰均有鼠标悬停/键盘聚焦说明，介绍含义及调高调低的影响。
- 通过启动器运行时，设置自动保存到此文件夹的 `无人机参数.json`，包含全部飞行参数、画质与反向俯仰。面板显示「已保存到本机文件」才表示写盘成功。重启或换端口后会从文件恢复。直接打开独立 HTML 时只能使用当前浏览器存储。文件夹需要可写；该文件已纳入 Git 跟踪，调整参数后提交即可把配置一并上传。旧版的 `.nightflight-settings.json` 会在首次启动时自动迁移过来。
- 保存已用重载、全新浏览器环境、服务重启并更换端口验证。测试使用独立临时配置，不会覆盖你实际使用的本机配置文件。

## V4 下落、滑行与拉升反馈

- 机体前后阻力改为 1–16 档，低档按 1–2–5 序列递减：1 档 0.0001×、2 档 0.0005×、3 档 0.001×、8 档 0.05×（旧版最小值）、11 档 0.35×（出厂默认）、16 档 2×。左右/上下阻力倍率默认分别为 0.7 / 0.8。持续下落时，垂直方向的阻力由「终端下落速度」单独调节。倍率是练习型近似，未按具体真机风洞或飞行数据标定。
- 高速收油后保留速度惯性，重力和空气阻力连续改变轨迹，不直接清零速度，也不设置下落速度硬上限。推力仍按原线性映射和电机响应建立，没有额外加一个虚构的“推力冲击”。
- 普通低帧率下补齐 240Hz 物理步进；单次画面停顿超过 250ms 时会明确暂停，避免旧版静默丢失模拟时间或追赶过大积压。严重卡顿会停桨并暂停；恢复流畅后油门归零并重新解锁，或点手机复位后重新起飞。
- 新增垂直速度、垂直加速度。负的垂直速度代表下降；下落时负速度绝对值增加，接近终端速度后加速度逐渐接近 0。
- 电脑「运动记录」显示最近约 20 秒的侧视轨迹，横轴为水平累计路程、纵轴为高度，自动缩放。记录总量最多 600 条（约一分钟），可导出 JSON，包含原始三维位置、速度、油门、实际推力和加速度。复位会清空。它是轨迹图，不是第三人称三维重播。
- 电机音量/音色跟随实际推力，风声跟随空速，收油后仍有滑行风声。需在电脑点一次「开启声音」；手机不能替电脑解除浏览器音频限制。相机保持刚性 FPV 安装关系，未添加假晃动或自动改变视野。
- V4 已回归手机起飞、断连暂停和新增参数保存。完整四电机混控、真实转动惯量、PID、桨洗、电池和动力标定留待后续。

在「飞行调校」可将飞行帧率上限设为 60 FPS。这个选项独立于画质，画面分辨率和效果仍按画质档渲染，飞行物理继续以 240 Hz 更新。默认跟随屏幕。
